DEVELOPING A MACHINE LEARNING APP
OilPrice Insight: Predicting the Next WTI Crude Oil Price

Victor Israel
November 13, 2026


1. NAME AND PURPOSE OF THE APPLICATION
The application is OilPrice Insight. This application predicts the next reported
spot price of WTI crude oil. Understanding the future price of oil is important
to the global economy because the price of oil impacts international
trade and transportation as well as manufacturing and industrial production.
Since oil prices impact many sectors of the economy, predicting oil prices
highlights challenges in making other economic predictions. The application
parses and analyzes historic oil prices, uses the information to create and
train a machine learning model, and makes predictions using the trained
model. The application evaluates how well the model captures historic prices
to estimate future prices. The application is a demonstration of creating a
prediction system using Python and an open source dataset. It is not a system
to actually predict oil prices.


2. ALGORITHMS USED
The focus algorithm is Random Forest regression. This algorithm creates a
combination of predictions made by several decision trees. Random
Forest is able to identify non-linear relationships and interactions
between financial data. When using the Random Forest algorithm,
interpretations from various components of the algorithm are averaged to
determine an overall prediction. Unlike other regression algorithms, Random
Forest allows the use of data with various and unrestricted measurement
scales. The implementation of Random Forest also eliminates the need to
standardize data. Overall, Random Forest is considered a more efficient
regression algorithm (scikit-learn developers, n.d.-a).
In this application, Random Forest is used to predict price changes from

currently observed financial data. Unlike other price prediction
applications, the main focus of this application is to generate
short-term price forecasts. Overall, the price predictions generated by
this application may not be completely accurate. A persistence
baseline is included for comparison. This baseline predicts that the
next price will be equal to the previously observed price. A price
prediction algorithm is generally considered better than a
persistence baseline. This application uses both chronological
testing and time-series cross-validation. Random Forest is also
considered more appropriate to use for time-series data and
cross-validation (scikit-learn developers, n.d.-b).
The Random Forest settings are hard coded in the Python program. 
These settings are a good starting point for a random forest model, but do not reflect an optimal model.

3. DATASET INFORMATION

3.1 Dataset Source and Link

The dataset contains Cushing, Oklahoma spot prices for the WTI crude oil price. The crude oil spot prices are published by the U.S. Energy Information Administration (EIA). The spot prices are available on the Federal Reserve Bank of St. Louis as series DCOILWTICO (Federal Reserve Bank of St. Louis, n.d.). This series is published by the EIA and is available at (U.S. EIA, n.d.). For this project, a published CSV file is available at (datasets contributors, n.d.) and is linked to the EIA. The published CSV file is dated November 2022 and contains spot prices through November 11, 2026. The prices in the CSV file were checked against FRED Spot Price series, which is published by the St. Louis Federal Reserve Bank and contains Spot Prices through November 10, 2026.

3.2 Number of records The file contains 1,214 dated price observations from Jan 3 2022 to Nov 11 2026. During the initial validation, the file had no empty or wrong records, and no repeated date records. After using the first 19 observations to generate lag and rolling window inputs, and keeping the last observation for later use, a total of 1,194 training samples were generated. Among the 1,194 samples, 955 were used for model training, while the remaining 239 samples (testing data) were used for model testing. 3.3 Number of features The input file has two fields, Date and Price. The model uses 13 features, which are extracted from historical and recent price observations. The model's output or target, that is, next observed price change is captured in the field Date. Date field is used for sequence alignment, and for plotting and representing prices over time. However, the field is not used as a model input.

3.3 Number of features

The raw file has two columns: Date and Price. 13 Numeric features were created based on historical prices. The model predicts the next price change. The model does not use the Date feature. Date is used to organize and display data. The model uses the features to make predictions.

3.5 Preprocessing Steps

 The application uses Pandas to read the CSVs and verify the presence of the required columns. The application makes type changes to the columns representing Date and Price to native Python Date and Float types, respectively. It removes the rows having invalid values and/or Duplicates, sorts the records in ascending order of Date and retains the last instance in case of ties. No invalid rows and no duplicate rows in the Samples provided. It has been reported that the application will not remove atypical and extreme market prices.

 Based on the training set, it creates training set features, viz. Lagged prices, price differences, rolling averages and rolling standard deviations. The first 19 observations are not considered for training. The last observation is kept for generating the forecast. Tree based regression algorithms have been reported to not require normalization; hence normalization is not performed.

 The training set is further partitioned into Train (80%) and Test (20%) sets. The model is trained using the first portion of the Train set. The last 60% of the Train set is used to define the reaming 4 folds for expanding window cross validation. Given the nature of the training data, it has been ensured that later observations are not used for model evaluation.

4. LIBRARIES, TOOLKITS, AND FRAMEWORKS
The main programming language is Python. Other key technologies include: Pandas (CSV input/output and data manipulation), NumPy (advanced mathematical computations), and Matplotlib (plotting). Additionally, the application leverages argparse and pathlib (command line arguments and file path manipulation), Scikit learn (random forests and other statistical computations), and time series (various forecasting computations).

 The application is a command line program. The data and resources required to run the application are loaded on the machine, therefore, no internet connection or external compute resources (i.e. Cloud, GPU, etc.) are required. The included CSV allows the application and its processes to be reproduced. The application and its dependencies are described in the requirements file.

 5. APPLICATION ARCHITECTURE

The application functions are small and composable. The primary functions of OilPrice Insight are: reading a dataset (read_prices() function); generating predictors and a target (build_features() function); and training a random forest model (new_model() function). The cross_validate() function computes forecast errors (i.e. MAE and RMSE). Other helpful functions for diagnostics include: determining the importance of features; and generating actual vs. predicted graphs.

Feature preparation includes retaining 20% of the recently labeled data
for testing. Random Forest models learn transformation of an asset’s
price by learning examples from the past. The unknown, or missing,
values in the test set are replaced with the price observed on the forecast
date, and the price change predicted by the model. For comparison,
the persistence baseline is also computed. The application computes
MAE, RMSE, and R2, and writes the results to a file, comparison chart,
and CSV. The CSV contains the price change predictions.

The backtest is repeated multiple times and the finalRandom Forest model is
trained on the entire data set. Like the other models, price transformation
of the recently observed price is learned. When reporting test results,
the Random Forest model fitted on the recently observed data is not
substituted by the previously fit model.

Results of the backtests are saved in a "results" folder. Each backtest contains
a text file containing command line output, and multiple images.
The source code is readable, and contains comments. The source code also
validates the CSV file containing the data used in the backtest. If the
CSV file is invalid or missing, an error is displayed.

6. INSTRUCTIONS FOR RUNNING THE APP

The following steps apply to a computer with Python 3.10 or later installed.

1. Download and extract the complete project folder.
2. Keep commodity_price_app.py, wti_daily_2022_2026.csv, and
   requirements.txt in the same folder.
3. Open Command Prompt or a terminal in that folder.
4. Create a virtual environment:

      Windows:  py -m venv .venv
      macOS/Linux: python3 -m venv .venv

5. Activate the environment:

      Windows Command Prompt: .venv\Scripts\activate
      macOS/Linux: source .venv/bin/activate

6. Install the Python packages:

      python -m pip install -r requirements.txt

7. Run the program:

      python commodity_price_app.py

8. Read the results printed in the terminal. Open the results folder to see
   the saved graphs, forecast dashboard, text summary, and test CSV.

Optional: To use a different CSV or save files to another folder, run:

      python commodity_price_app.py --data my_prices.csv --output my_results

The output must have Date and Price columns, or the equivalent FRED columns.
 names observation_date and DCOILWTICO. The most recent prices will allow you to generate your own
forecast. Additional downloads will not be necessary. The included results and this
read me give similar instructions.

7. RESULTS

The program was successfully executed with the bundled dataset. After preprocessing, the model was trained with 955 observations, with forecasts in the range of Jan 31, 2022 to Nov 26, 2025. The test set was not shown and contained 239 forecasts in the range of Nov 28, 2025 to Nov 10, 2026. For each of the test forecasts, the model identified the next observation that was published, and thus, verified the forecast.

The MAE for the training set is lower compared to the cross-validation set. In cross-validation, later folds may reflect more difficult conditions to forecast. 8. DISCUSSION AND INSIGHTS
The model is able to capture historical prices, however, it is unlikely that the model is capturing meaningful signals beyond a naïve forecasting strategy. The Random Forest model achieved an R-squared of 0.952 on the out-of-sample data set. As discussed earlier, the persistence baseline achieved a slightly lower mean absolute error of 2.423 compared to the Random Forest model which had a mean absolute error of 2.503. The difference between the two was approximately 0.08 dollars per barrel. Thus, from a practical standpoint, the Random Forest model was not generating forecasts which were superior to the persistence baseline.

 From an investor or trader perspective, achieving a high R-squared is desirable; however, in this project, achieving a high R-squared does not necessarily mean that the Random Forest model is capturing relevant information. In fact, theRandom Forest model may be capturing signals which are broadly related to prices and production, but it may not capture relevant information which is not reflected in historical prices, such as, unexpected geopolitical changes, inventory reports, weather, or changes in consumer demand. These may suddenly and rapidly effect prices.
The evaluation has its limitations. The backtest shows it can predict, at least,
one published observation. It makes the strong assumption that actual prices
 feedback the system and are immediately used to make the next prediction.
With the lack of new information, it cannot make extended outlooks (i.e.
weekly or monthly). The test examples reflect sequential order, but the model
does not adjust for latency. Depending on the dates and commodities analyzed,
 the results may reflect low error levels.
It may be beneficial to lower the error levels by training the model with other
macroeconomic indicators. Additionally, other methods such as SVR and
Algorithmic trading may reduce prediction error. Lastly, it may be worth
investigating if predicting price changes is better than predicting prices.
Other hyperparameters may also be altered during training.
The final test set was left untouched until the end.
To validate the model, it would be beneficial to analyze mistakes made during
different market conditions. It also would be valuable to test the model for
position error. Model accuracy could be tested over different time frames
(i.e. weekly or monthly). Other additions to the model could include
automating the download and updating of market data, and the creation of
an interactive graph.
These are potential enhancements to the model and are not representations
of the model as it stands.
The model provides a good example of a complete machine learning project.
 It provides an easy to understand example of accessing and preparing data,
teaching machine learning algorithm model building, and evaluating model
forecasts and performance. Improving the model to include more variables
may have provided better forecasts. Although, improving model forecasts
is not the main objective of this project. In fact, evaluating the model
restrictions and limitations is more important. Limitations of the model
are discussed.
